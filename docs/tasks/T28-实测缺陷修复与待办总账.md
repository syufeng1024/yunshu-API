## 2. 本卡修复项（5 项，逐项做到）

### A · P0 布局空白带

**现象**（可复现，本地 Chrome 1408×672）：
1. 打开 `/console/playground`；
2. 按 `PageDown`；
3. 页面内容整体掉到视口底部，**上方约 500px 全白**，需要再滚一次才能看到内容；
4. 同样现象在 `/pricing` 上表现为标题区与卡片区之间出现约 90px 的空白带。

**不要只看截图就下结论**。要求按这个顺序定位：
- 用浏览器 DevTools 量 `.min-h-screen`（`ConsoleLayout.tsx:28`）与内层 `flex-1`（`ConsoleLayout.tsx:73`）的实际高度；
- 检查 `PlaygroundPage.tsx` 的 `space-y-5`（`:448`）与 `grid gap-3 sm:grid-cols-2`（`:454`）在各断点下的行高；
- 检查是否存在 `min-h`/`h-` 类与内容高度冲突，或 `sticky` 侧边栏（`:29` 的 `md:h-screen`）挤压主滚动区。

**判定**：修完后 `PageDown` 一次应停在内容自然位置，**不得出现超过 24px 的无内容空白带**。

### B · P1 首页「接入线路 0」

**位置**：`web/src/pages/site/LandingPage.tsx:92` —— `{ label: '接入线路', value: formatInteger(endpoints.length) }`

**现状**：数据源 `GET /api/public/endpoints` 返回空数组，页面直接渲染 `0`，在落地页首屏显眼位置，破坏可信度。

**要求（二选一，优先后者）**：
1. 后端补 `t_protocol` / endpoints 种子数据，让数字真实；
2. 若短期无数据，前端在 `length === 0` 时改渲染 `--` 并把标签改为「接入线路（筹备中）」，**不得展示 0**。

**验收**：首页首屏三个统计位不得出现 `0` 这个具体数值。

### C · P2 响应头重复

**现象**：流式调用返回的响应头里 `X-Request-Id` 与 `X-Trace-Id` **各出现两次**（实测 `curl -D` 输出可见）。

**根因**：`internal/control/console/playground.go:389` 的 `copyHeaders` 用 `dst.Add(name, v)` 追加，而 Session 中间件已经在 `w.Header()` 里设过同名头，透传时又追加一份。

**要求**：
- 对**端到端语义上应唯一**的头改用 `dst.Set`（覆盖），至少 `X-Request-Id`、`X-Trace-Id`；
- 对其余头保持 `Add`（如 `Set-Cookie` 可能合法多值，不得一刀切成 `Set`）；
- 增加测试断言：响应头中这两个 key 的 `len(values) == 1`。

### D · P1 种子渠道密钥是明文占位，重建即坏

**现象**：全栈重建后，渠道 `upstream_key_enc` 的值是 `local-dev-placeholder`（明文占位，21 字节）。gatewayd 解密要求 `v1:` 信封格式，于是 P15 报 `upstream_key_enc_not_v1`，调试台与所有上游调用全部 503。

**要求**：让 `scripts/seed-demo.sh`（或渠道种子 SQL 的执行路径）在写渠道密钥时**必须走 `cmd/keytool seed-channel` 的加密路径**，不再写明文占位。若种子 SQL 里写死了占位符，改为由脚本在播种后调用 keytool 覆盖。

**验收**：清空数据卷 → 重新 `up --build` + 播种 → 直接调 `/api/console/playground/chat` 能通，不需要任何手工补丁。

### E · P2 种子路由的 region 口径

**现象**：`t_route.region` 必须是 `DOMESTIC`（大写），写成 `cn` 会被 `internal/gw/p12_router.go:72` 硬排除，报 `no_available_upstream`。

**要求**：如果种子数据/文档中出现路由 region 示例，一律用 `DOMESTIC`；在 `docs/schema.md` 的 `t_route` 条目补一句枚举说明，避免下次再踩。

## 5. 硬约束

1. **不要用「加 padding / 改高度」的方式掩盖布局问题**。必须找到真实原因（哪个容器的高度或滚动上下文不对）再改。若实现方判断需要改全局布局，先报回说明影响面。
2. **`copyHeaders` 不允许整体改成 `Set`**。只对明确的单值头（`X-Request-Id`、`X-Trace-Id`）覆盖，其余保持 `Add`，否则会破坏 `Set-Cookie` 之类的多值语义。
3. **种子修复必须端到端可重现**：改完后从空卷重建一次并跑通调试台，才算完成。只改脚本不验证 = 没做。
4. **不得为了修 B 项而在前端硬编码统计数字**。要么后端给真数据，要么显示占位符。
5. **不得改 `/v1/*` 公网契约**；`playground.go` 的改动只限响应头处理后端到端透传语义。
6. **文件域边界**：只碰 §4 的 7 项。禁止碰 `internal/gw/**`、`deploy/k8s/**`、`internal/platform/migrate/**`（`docs/schema.md` 仅改说明文字）。
7. 改完跑 `bash scripts/check-eol.sh`，退出码必须 0。
