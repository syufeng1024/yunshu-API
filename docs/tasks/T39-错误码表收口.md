### 3.1 代码：`upstream_key_unavailable` 补生产者

1. `internal/dispatch/dispatch.go:433`：`decryptKey` 失败分支的 `apierr.New(apierr.CodeConfigUnavailable)` 改为 `apierr.New(apierr.CodeUpstreamKeyUnavailable)`。
   - **只改这一处**。`:166`（`targets()` 快照/渠道缺失）与 `:445`（`buildBody` 失败）**保持 `config_unavailable`**——那是路由/映射配置问题，不是凭据问题。

2. `internal/dispatch/usagerecord.go` 的 `attribution()`：为 `CodeUpstreamKeyUnavailable` 增一条显式分支 → **`("ROUTE", "PLATFORM")`**。

3. 用例（`internal/dispatch`）：
   - 构造一个 `upstream_key_enc` 存在但**解不开**的渠道（例如 KEK 与密文不匹配，或信封前缀正确但内容损坏），断言：HTTP **503**、`code == "upstream_key_unavailable"`、`t_usage_record` 那一行 `biz_code` 同值且 `fail_stage='ROUTE'`、`fail_owner='PLATFORM'`。
