## 1. 目标

PRD §6.2 F14-6 边界 4 原文：

> 该用户的专属渠道**全部不可用时**，退回 §3.4.1 既有降级路径处理，**不得静默回落到共享池冒充专属**。是否允许回落做成渠道表单上的二选一开关（**默认不允许**）；选「允许」时**每次回落必须落日志计数**，供月度对账举证。

现状：`fallback_allowed` 字段**只被解析进快照、从未被读取**（`internal/gw/catalog.go:103`），P12 路由遇到专属渠道不可用时直接让共享池补位，既不判断开关，也不落任何记录。

## 3. 决策（D-29）

1. **默认不允许回落**：`fallback_allowed = false`（含字段缺省）时，若该用户所属的专属渠道全部不可用，**不得让共享池候选补位**；候选集为空后走既有降级路径（沿用现有错误码选择逻辑，不新造码）。
2. **允许时才回落，且每次必须留证**：`fallback_allowed = true` 时保留共享池候选，但每一次回落都要
   - 写一条结构化日志（字段至少含 `request_id`、`user_id`、`model`、`excluded_channel_ids`、`reason`）；
   - 递增一个计数（指标名自定，需可被观测；`internal/obs/metrics` 已有设施，按既有命名风格加）；
   - **一次请求只计一次**（不要按候选渠道数重复计数）。
3. **判定口径**：某渠道是「专属渠道」当且仅当 `DedicatedScopeMode == SELECTED` 且 `IsDedicated(ch.ID, userID)` 为真。它「不可用」指被启停、熔断、region、分组、stream 任一条件排除（即走到 `continue` 的所有分支）。
4. **不改变**：名单外用户看不到专属渠道（现状保持）；专属渠道正常可用时行为完全不变；计费、限流、SLO 分母一律不动。

## 5. 硬约束

1. 不得改 `/v1/*` 的响应契约（错误码、字段、HTTP 状态）；回落被禁止时复用**既有**错误码。
2. 不得新增配置键（开关已存在于 `t_channel.fallback_allowed`）。
3. 日志与指标**不得**包含上游 Key、用户凭证、完整请求体。
4. 不得让「不允许回落」影响**没有专属渠道**的普通用户（这是最容易引入的回归）。
5. 既有断言只许加强；`bash scripts/check-eol.sh` 退出码 0；不 commit / 不 push。

**偏离（已接受）**

1. 日志 schema 新增两个固定键 `reason` / `excluded_channel_ids`，会出现在所有 warn/info/error 行（缺省空串）。`log_test` 的键数断言由 14 改为 16 并补两键校验——是**加强**不是削弱；固定长度截断防换行伪造。
2. 多专属渠道时按「全部允许才回落」合并（任一 `false` 否决），即偏默认拒绝。PRD 未定义混合配置口径，已写入代码注释。
3. 计数器只在「确实存在可回落的共享候选」时 +1；无共享候选时请求直接降级，不计未发生的回落。
