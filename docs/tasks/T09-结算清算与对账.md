## 4. 硬约束（违反即驳回）

1. **资金真相只在 DB**：预扣/结算/释放的权威是 `t_ledger_entry`；Redis 只做拦截与兜底哨兵（GR-02）。代码注释必须写死这句。
2. **结算幂等键 = `request_id`**：重复执行同一 `request_id` 的结算必须是 no-op，且不产生第二条 CONSUME 流水。
3. **`consumed==0` 的释放必须先校验预扣流水存在**，否则拒绝释放并报错。理由：释放一个未发生的预扣等于凭空加钱。
4. **P28/P29/P30 失败不影响资金**：日志与指标写入失败只记 WARN + 指标，**不得**回滚结算。
5. **背压 5000 条**：积压超阈值时网关对新请求 503；已在途请求不拒绝。宁可短暂拒服务，不制造对账缺口（GR-03）。
6. **悬挂恢复必须先 `SET NX hold:recover:{request_id}`**，多副本不得重复处理同一悬挂。
7. **悬挂三态必须区分**：①有 `usage` → 正常结算；②无 `usage` 且上游已断 → 全额释放；③上游仍活 → **不释放**，延长 `expires_at` 并等下一轮（最多 3 轮后转人工）。
8. **日对账 8 条断言逐条实现**（金额守恒、流水和 == 余额、批次余额和 == 账户余额、无孤儿流水、无未结算成功请求、上游账单差 ≤ 阈值、日额度快照一致、配置版本可回溯）。
9. **对账任务只读**：除写 `t_reconcile_diff` 与告警外**不得**修改业务数据；修正一律走冲正分录 + 人工确认。
10. **冲正不改历史**：append-only 不得被 `UPDATE`/`DELETE` 破坏；冲正为新增 `REVERSAL` 流水，`origin_entry_id` 指向原流水。
11. **账本不分区、不 DROP**：`t_ledger_entry` 三个唯一键均不含 `created_at`；365 天是在线**查询**窗口而非保留窗口。
12. **日志库不分区、不 DROP PARTITION**：用分批 `DELETE`；`uk_ur_request(request_id)` 必须全局唯一。
13. **不做跨库 join**：日志查询所需维度（模型名/Key 名）冗余进日志行。
14. **不做调价差额纠偏**（GR-04）：按 `t_usage_record` 的配置版本号事后圈定范围，不自动补扣/退。
15. **jobsd 单实例执行**：所有带副作用的定时任务必须走选主；`无选主` 仅允许纯读任务。
16. **赠送积分到期清零不可退**，且**不影响**充值积分批次；两者不得写成同一段逻辑（PRD §3.2.1 两套有效期）。
17. **清理任务必须幂等可重入**：中断后重跑不得漏删或重复计数。
18. **`0021` 只允许建这两张表**：不得顺手改 0001–0020，不得建第三张表。建完把 `migrate_test` 的 `wantMigrationCount` 同步为 **19**，并更新 `docs/schema.md` 的「56 张表 / 19 条迁移」。
19. **表名必须写 `t_reconcile_diff`**：TDS §5.4.1 的写法；卡内旧文写 `t_recon_diff` 是笔误，不得据此建表。
