## 1. 目标

实现「**业务未定项只影响配置、不影响代码**」这一架构前提的落地机制：34 个配置键的注册、校验、下发、快照与热更新，以及 C1/C2/C3 三种落点的策略注册表。做完本卡，改一个数值不需要发版；新增一种扣减策略只需加一个实现文件 + 一条配置值。

## 4. 硬约束（违反即驳回）

1. **注册方向不可倒转**：`internal/config` **不得** import 任何业务包；业务包在自己的 `init()` 里反向注册。这样 `config` 保持零依赖、可单测。
2. **键定义单一来源**：34 键只能在 `key.go` 出现一次；`grep -rn '"billing.prehold_ratio"' internal/ --include=*.go | grep -v internal/config/key.go` 必须为空（消费方一律引用常量）。
3. **`quota.overdraft_warn_days` 的特殊处理**：`cfg_namespace='UNASSIGNED'`；任何写入返回 `config_value_invalid`；装载时**不得**进入任何 namespace 快照（否则等于"接受却无人读取"）。
4. **运行时可写白名单恰为 12 键**：`billing.deduct_policy`、`billing.prehold_max_ratio`、`gw.upstream_timeout_ms`、`gw.client_timeout_budget_ms`、`gw.max_inflight`、`gw.drain_deadline_ms`、`log.retention_days`、`quota.daily_meter`、`quota.key_daily_mode`、`quota.reset_scope`、`quota.reset_tz`、`quota.rate_limit_order`。其余 22 键写入一律拒绝，**包括 TA-1.1 的 4 个新键**。
5. **`gw.retry_max` 不进白名单**：1→2 会让全平台上上下游调用量涨约 10%，属随版本发布的开关。
6. **`pricing.cache_billing_enabled` 不进白名单**：误开会导致**全量请求少收钱**且不报错，只能走 `t_config_publish` 灰度。
7. **发布顺序固定**：必须 `SET 快照` 先于 `INCR 版本号`。反过来（先升版本后写快照）会让节点拉到「新版本号 + 旧快照」并接受，出现最长 300s 的错配。
8. **Pub/Sub 不是唯一通道**：必须配合 30s 轮询 `cfg:ver`。订阅者掉线丢消息是常态，不得依赖。
9. **快照不可变**：`Snapshot` 一旦发布不允许原地修改字段（否则读到一半的 goroutine 会看到撕裂数据）；更新一律换新指针。
10. **单 namespace 快照体积 < 256 KB**，超限时 `publish` 返回错误并提示分片，**不得**静默截断。
11. **`price:{model_id}` 只存标准价**：取价是 `标准价 × gp(来自 K13) ÷ 10000` 的一次乘法；**不得**把倍率乘进缓存值（否则缓存键要带分组维度）。
12. **税率口径 `pricing.tax_rate_multiplier`**：默认 `1.00`，唯一作用点在成本侧计算；函数体首行写 `// TODO(Finance): 税率口径待财务签署（PRD D.1 第 15 项）`；**CI 锁默认值**（有人改默认值即测试失败）。
13. **逻辑专属文案**：`i18n.DedicatedCopyPublic` 单一常量 + `TODO(Legal)`；本卡只落常量位，不写具体文案。
14. **`quota.rate_limit_order` 默认 `concurrency>rpm>tpm>daily`**：该值只影响「拦不拦」的判定次序，**不影响**对外报哪个码（对外取恢复最晚者，见 T10）。

```bash
go test ./internal/config/... -race -cover
grep -rn '"billing\.' internal/ --include=*.go | grep -v internal/config/key.go || echo "OK: 无字面量"
go list -deps ./internal/config | grep -E "internal/(gw|ledger|control|redisx)" || echo "OK: config 无业务依赖"
```

## 7. 禁止事项

- 不得让 `internal/config` 依赖 `internal/redisx` 之外的业务包（Redis 访问通过接口注入）。
- 不得为"方便"给某个键加一条特例 `if`，所有特例必须进 `key.go` 的元数据表。
- 不得在快照里放**渠道上游 Key 明文**；快照只带路由与价格所需的非密字段（`t_channel` 的密文列不进快照）。
- 不得实现「配置变更即时生效（0 秒）」——目标 P99 < 30s，即时性不是需求。
- 不得自行增加第 35 个配置键（需先改 TDS §3.7，由交付总监执行）。
