## 2. 必须先定：规则从哪来（需求方三选一）

| 方案 | 形态 | 代价 | 评价 |
| :--- | :--- | :--- | :--- |
| **A. 关键词库 + 本地规则** | 新增规则表（或配置文件），网关按 `rule_id` 匹配 messages，命中写 `t_content_policy_hit` | 中：要设计规则存储、版本、热更新；漏判率高，只挡得住显式词 | 最省外部依赖，但「内容安全」形同虚设，涉政/涉黄变体挡不住 |
| **B. 外部内容安全服务**（阿里云内容安全 / 腾讯云天御 / 自建模型） | 网关在 P04 后调用，超时/失败必须有降级策略 | 大：供应商、计费、网络、可用性 SLA、超时预算挤占 P01 的 120s | **合规上最可靠**，但引入外部依赖与新的失败模式 |
| **C. 先 B 后 A** | 先接一家服务，本地关键词库作为快速兜底 | 最大 | 长期形态，V1.0 可能过重 |

**裁定前不得写代码**。理由：本项一旦落地，「哪些请求被拒」是**对外的合规承诺**，用假规则充数（例如永远返回 false 的钩子）比不做更糟——它会让 F19-3 的申诉入口看起来有数据，实际一条都没有。

## 3. 一旦选定，范围（按 B 为例）

| # | 内容 |
| :--- | :--- |
| 1 | 新增 `gw.PolicyChecker` 接口（`Check(ctx, text string) (Verdict, error)`），通过 `gw.Deps` 注入；**`nil` 表示未启用**（不是「全部放行」的假实现，而是显式未配置，启动时 WARN） |
| 2 | P04 之后、P05 之前执行：命中 → 写 `t_content_policy_hit` → 返回 403；**必须在 P09 预扣之前**，保证不计费不预扣（PRD §10.1 ④.1） |
| 3 | 超时/失败策略：调用失败时**放行并 WARN**（fail-open）还是**拒绝**（fail-closed）必须显式选定并写进卡；建议 fail-open + 指标告警，理由：内容安全服务故障不应让全站不可用 |
| 4 | 命中行字段：`rule_id` / `rule_version` / `category` / `severity=BLOCK` / `matched_excerpt`（脱敏 ≤255）/ `snippet_sha256` / `snippet_offset` / `client_ip` / `action=BLOCK` |
| 5 | `hint` 指向工单页（PRD §10.1 ⑤） |
| 6 | 用例：① 命中 → 403 + 该码 + `t_content_policy_hit` 有行 + **账本零流水、预扣未发生**；② 未命中 → 正常转发；③ 服务超时 → 按 §3.3 的策略断言；④ 申诉：工单创建后 `action` 变 `APPEAL_PENDING` 且能按 `request_id` 反查到 `rule_id` |

## 4. 硬约束

1. **禁止空钩子**：不允许写一个永远返回「未命中」的实现来把码表点亮。
2. **不得**在命中路径上产生任何资金动作（`t_ledger_entry` 新增行数必须为 0、`t_prehold_hold` 无行）。
3. **不得**存原始消息全文；`matched_excerpt` 必须脱敏且 ≤255 字符。
4. 若方案需要新表/新列，必须走迁移并重生成 `checksums.golden`、同步 `guard_test.go` / `migrate_test.go` 的表数与版本数。
5. 超时预算不得挤占 P01 的 120s 总预算（要么单列短超时，要么在预算内扣减并记录）。
6. 不 commit / 不 push。

## 5. 验收口径

| # | 查什么 | 通过标准 |
| :--- | :--- | :--- |
| 1 | 码有真生产者 | 构造一次真实命中 → 403 `content_policy_violation` |
| 2 | 不计费 | 同一请求前后 `t_ledger_entry` 行数不变、`t_prehold_hold` 无新行、`t_usage_record` 无该 request_id（或按 PRD 口径记 0 消耗） |
| 3 | 申诉闭环 | 工单创建 → `action=APPEAL_PENDING`；列表能显示 `rule_id` / `category` |

| 5 | 降级 | 服务不可用时行为与卡内选定策略一致，且有 WARN 日志与指标 |
