## 1. 目标

把官网 5 页做成「**不写死任何数值**、**不承诺未验证的能力**」的转化入口：首页讲清是什么并给价格、定价页让人能对比四档、文档页让开发者 3 分钟跑通第一个请求、登录页完成注册与体验积分领取、集成页让已有工具的客户一键改 base_url。

## 2.1 首页区块（基线 = PRD §4.1，顺序与形态可自行取舍）

PRD §4.1 要求的区块**一条都不能少**：

```
导航 · Hero · 核心能力 · 模型价格表 · 套餐限流表 · 调价公告位
· 接入点与线路 · 工具集成入口 · 底部 CTA · 页脚
```

**顺序不强制**。若参考站的做法更好用（例如把工具入口提前到第二屏、在 CTA 前补一个「快速接入三步」），可以自行调整——验收只看区块内容是否齐备、功能点是否成立，不看排列次序。不必为了"像参考站"而新增 PRD 之外的区块。

## 4. 硬约束（违反即驳回）

1. **不写死任何数值**：价格、四档额度、模型上下文长度全部来自 API。bundle 扫描（T17 硬约束 6）为最终判据。
2. **首页价格表只显示 `standard` 单价**：不出现合约价、内部价（PRD F1-5）。
3. **切「图像」分组只显示图像模型**；请求向量模型 → 404 `model_not_found`（V1.0 无向量）。
4. **`CATALOG_ONLY` 模型在三处都不得出现**：首页、模型广场、文档示例（F1-6）。
5. **接入点区块不显示「可用」状态**：只展示线路与地址（F1-4）。任何"99.9% 可用"类文案不得出现。
6. **推荐区块**：按 `(recommend_weight DESC)` 展示；**全部权重为 0 时整块不展示**，不空占版位（F1-7）。
7. **定价页四档必须一张表**：含 RPM / TPM / 并发 / 日额度 / 积分 / 价格六列，不得拆成大段文字块（F2-2）。
8. **套餐 CTA 分流**：未登录 → 跳注册并带套餐标识；已登录 → 跳 `/console/recharge` 并预选该档（F2-1）。
9. **文档示例域名与 Key 均为虚拟值**：页首必须有「示例为虚拟值」声明（F3-3）。示例 `base_url` 用 `https://api.yunshu.dev/v1`。
10. **文档章节切换不整页刷新**（F3-2）：用客户端路由，保持滚动位置合理解释。
11. **复制必须精确**：剪贴板内容与代码原文逐字节相等（含缩进），提示 2s 内消失（F3-1）。
12. **集成页恰 5 张卡**，不得增减；卡片内容**来自文档第 9 章同一数据源**，不得写第二份文案（F4-5）。
13. **一键导入不得泄露 Key**：抓 DOM / URL / localStorage / 埋点均不得含明文 Key；跳转后参数即丢弃（F4-2，**安全项，必须有自动化测试**）。
14. **未登录时一键导入置灰**并提示先登录（F4-4）。
15. **深链模板由后台配置**：改参数名后前端不发版即生效（F4-3）——模板来自 API。
16. **资质入口不展示**（证照未提供），不留空链。
17. **品牌与 Logo 规范**沿用 T17：Header 必须 Mark + 文字标，`aria-label="云枢 API 首页"`。
18. **不得出现未上线功能的承诺**：分销/代理、团队、订阅制、向量模型、境外模型一律不提。
19. **参考站的营销元素只能借版式，不能借承诺**（详见 `ref-frontend-structure.md` §4）：不得出现「注册即送 X 元」「X 折起」「低至」「代理合作」「加盟」「许可证编号」「即将支持更多工具」。体验积分必须表述为「**主动领取 7,000 体验积分（7 天体验版）**」，不得写成注册即送现金等价物。**额度以 PRD §3.2.1 的 7,000 为准**——附录 E.1 里 `account_not_verified` 的 hint 仍写「10 万」，属已作废旧口径（见 `errata.md` E-06），不得据此渲染。
20. **工具相关只提 5 个名称**：Cursor / Claude Code / Cherry Studio / NextChat / OpenAI SDK。若做了工具展示区，用静态展示即可；**不要**照抄参考站"重复成员填充走马灯"的手法——重复会让读者以为支持更多工具，违反 F4-1。不做展示区也可以，PRD 只要求"一句提示 + 跳转链接"。
21. **参考站的首页 FAQ 不照搬**：计费类 Q&A 按 PRD §4.2 放定价页，工具类问题在 `/integrations` 与文档第 9 章；首页再放一份会造成文案漂移（同 F4-5 口径）。
22. 区块标题写法可参考 §3 的三段式（小标签 / H2 / 副标题），**不强制统一**；同一页面内的标题层级保持一致即可。
23. **预览数据只能走 fixtures，不能写进页面**：页面组件内**禁止**出现价格、套餐额度、模型名等字面量；所有数值一律来自 `client` 的返回。fixtures 只在 `import.meta.env.DEV && VITE_USE_FIXTURES=1` 时生效，生产构建必须剔除（构建期断言 `dist/assets/*.js` 中不含 fixtures 的标记字符串）。
24. **fixtures 的数值必须是"契约样例"而非"编造的营销数字"**：价格表与套餐表按 PRD §3.2.1 取值，模型名用 `0019` 本地联调种子的两个示例模型（`qwen-max` 等），不得出现"快米兔""GPT-6 Astra"这类参考站的名字。

## 7. 禁止事项

- 不得把示例 Key 写成看起来像真实 Key 的格式（用 `sk-xxxxxxxx`）。
- 不得在官网提"免费无限"或"低至一折"（PRD §3.5 明确不做引流分组）。
- 不得给集成卡加"即将支持"的占位。
- 不得用图片承载价格表（会导致 F1-2/F1-3 无法验证）。
