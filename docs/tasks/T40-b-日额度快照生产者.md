## 2. 范围

**做**：一个按日结算的 job，把每个用户在某个 CST 自然日的用量固化进 `t_user_daily_quota`。

**不做**：不改 `checkR05`、不改表和迁移、不改 Redis 计数器、不动 429 拦截逻辑。

## 3. 设计必须回答的四个问题（卡内先给答案，实现照做）

1. **算哪些用户**：`stat_date = D` 当天在 `t_usage_record` 有行的用户 ∪ 当天有 `limit_micro` 变化（提额生效）的用户。只算前者会让「零用量但提了额」的用户缺行；只算后者会让 R05 的分母失真。
2. **`limit_micro` 从哪来**：取该用户 `stat_date = D` 当日的**起始额度快照**。若当天没有额度变更，等于前一日值；首日等于账户当前日额度（`t_credit_account` 或额度生效链）。**必须写清楚取自哪个字段**，不能算一个近似数。
3. **`used_recharge_micro` / `used_bonus_micro` 怎么拆**：`t_usage_record` 有 `consumed_recharge_micro` / `consumed_bonus_micro`（T09 落地，首次交付可能为 0）。若两列为 0 而 `consumed_micro > 0`，**不得**自行按比例拆分——`used_total_micro` 写总量、两列写 0，并在回执里报这个数据缺口（split 未落地属 T09 遗留）。R05 只比 `used_total_micro`。
4. **补算与重跑**：job 必须可按 `--date` 重跑，结果幂等（`INSERT ... ON DUPLICATE KEY UPDATE` 覆盖同一 `(user_id, stat_date)`）。默认每次跑「昨天」并顺带补最近 N 天缺失行（N 建议 7，理由：job 停机一周内能自愈）。

## 5. 硬约束

1. **不加迁移**。表和唯一键已存在。
2. **金额只用 int64 微积分**，禁止 float/decimal（D-07）。
3. **`stat_date` 一律按 UTC+8 折算**，与 `reset_at`（次日 00:00:00.000 UTC+8）保持同一口径；不得用 UTC 日期。
4. 不改 `internal/recon/` 任何文件（R05 只读，逻辑不动）。
5. job 必须走既有选主机制（`election.go`），不得裸起 goroutine。
6. **不 commit / 不 push**。
