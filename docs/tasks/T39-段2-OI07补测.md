## 2. 逐码做法（建议，可按实际代码调整）

### 2.1 `key_disabled`（gw）

`fakeAuth` 的 `records[KeyHash16(key)]` 用 `ST: "DISABLED"`（其余字段照 `authorizedAuth` 抄）。打 `/v1/chat/completions` → **403 + `key_disabled`**。
**必须**与 `invalid_api_key`（未知 hash）、`key_expired`（`exp` 已过）三态并列断言，证明不是「同一分支换个名字」。

### 2.2 `account_frozen_due_to_overdraft`（control）

登录一个 `t_user.status = FROZEN_OVERDRAFT` 的账号 → **402 + 该码**。
控制面测试夹具见 `internal/control/ctltest`。若登录路径造号成本高，可走 `mw/session.go:261` 的会话中间件路径（已登录后取用户时遇冻结），断言同一个码——**二选一，写清选了哪条**。

### 2.3 `idempotent_replay_unsupported`（gw）

**优先真链路**：非流式响应体 > `maxReplayBody`（64 KB，见 `internal/dispatch/dispatch.go` 常量）时不存 body，重放返回 `response_not_replayable` → `server.go:278` 映射为 **409 + 该码**。
若真链路需要拉 MySQL 幂等表且成本过高，**可退化为** `fakeIdem` 直接返回 `ReplayDecision{Status: 409, Code: "response_not_replayable"}`，但必须在用例注释里写明「只覆盖映射层，未覆盖 >64KB 的截断判定」，并在回执里列为遗留。

### 2.4 `upstream_tls_failure`（dispatch）

`httptest.NewTLSServer` 做上游，渠道 `base_url` 指向它；Dispatcher 用默认 transport（不信任自签 CA）→ `x509` 错误文本含 `tls:` → `classifyTransportError` 命中 `:759`。
断言：**502 + `upstream_tls_failure`**、`attempt.ErrorClass == ClassTLS`、`RetryDecision == DecisionNoRetry`。

### 2.5 / 2.6 `upstream_auth_failed` / `upstream_model_not_found`（dispatch）

复用既有 `fixedUpstream(status, body)`（见 `dispatch_test.go:681` 的 `TestUpstream400MapsTo400InvalidRequest` 写法）：

- `fixedUpstream(401, ...)` → 502 + `upstream_auth_failed`；顺带断言 `403` 也走同一分支（表驱动两行）。
- `fixedUpstream(404, ...)` → 502 + `upstream_model_not_found`。
两者都要断言 `attempts == 1` 且不重试。

### 2.7 `client_aborted`（dispatch）

用 `fakeupstream` 的 `ModeStreamStall`（已存在，见 `internal/fakeupstream/fakeupstream.go:31`）做上游，请求 context 在首批字节后取消。
断言以 **usage 行为准**：`biz_code == "client_aborted"`、`client_aborted == 1`；若响应已开始写出，HTTP 499 可能在 `httptest.ResponseRecorder` 上不可见——**不要为此改生产代码**，在注释里说明观察点选在哪一层。

### 2.8 `convert_failed`（dispatch）

**先读 `:456` 与 `:867` 两处**，确定可稳定触发的最小构造（`buildBody` 失败 vs 响应解码失败），再用 `fixedUpstream` 造对应 body。
**关键**：不得与既有 `TestMalformedBodyIs502WithoutRetry`（断言 `upstream_invalid_response`）撞车——必须断言到 `convert_failed`。如果两处实际上都无法在现有夹具下稳定触发，**如实报告「不可达」**并说明原因，不要写一个永远进不去的用例。

### 2.9 `auth_unavailable`（control）

让认证依赖不可用（DB 已关闭 / store 返回错误）→ 503 + `auth_unavailable`。用 `ctltest` 既有夹具注入故障，不要新增生产钩子。

### 8.4 反证暴露的真缺陷（交付总监直接修）

反证第 3 条的输出里发现：`upstream_all_failed` 的报文是 `"上游服务当前不可用，已重试 %d 次"` ——**`%d` 原样漏给了用户**。

- 根因：`classifyTransportError` 用 `apierr.New`（无参）构造 `upstream_timeout` / `upstream_all_failed`，而这两个 spec 的 Message 都含 `%d`；`Newf` 只在**有参数时**才格式化（`internal/apierr/error.go:54-60`）。HTTP 状态码那条路径（`upstreamStatusError`）用的是 `Newf`，所以只有「连接层失败」这条路径中招。
- 修法：`classifyTransportError(err, attemptNo int)`，两处 `New` → `Newf(code, attemptNo)`；`try()` 里把 `AttemptIndex` 提前赋值以便 `unaryAttempt` 取用（后续 `:323` 用同一个值覆盖，语义不变）。
- 断言：新增 `internal/dispatch/errmsg_test.go` —— 三个分类子用例 + 一条端到端（打 `127.0.0.1:1` 拿到真实 502 报文，断言无 `%d` 且含「已重试 1 次」）。
- 反证：把 `Newf` 改回 `New` → 三个子用例与端到端用例全部变红（报文里出现字面 `%d`），恢复后绿。
