## 4. 硬约束（违反即驳回）

1. **Key 明文只出现一次**：创建/轮换成功后弹窗显示并支持复制，**关闭后不可再查**；详情页只显示前 8 位 + 掩码（F6-3）。
2. **新建向导无「选分组」步骤**：四步为 名称 → 模型范围 → 有效期 → IP 白名单；分组在详情页只读（F6-2 / F6-6）。
3. **停用必须二次确认**；取消则状态不变（F6-4）。
4. **批量创建**：数量 1–20，结果页可**一次复制全部**（F6-5）。
5. **免费档 3 Key**：达上限时新建按钮置灰 + 提示升级；后端拒绝时展示 `hint`（F6-7）。
6. **实时值不伪装**：限流/用量接口失败时显示 `--` 与错误提示，**不得显示 0**（F5-2 要求"断网时图表报错而非显示假数据"）。
7. **概览无「来源渠道」标识**（V1.0 不实现该逻辑，F5-3）。
8. **模型广场**：排序 `recommend_weight DESC`；筛选后不退回录入序（F8-4）；`CATALOG_ONLY` 不出现（F8-3）；单价 1500 微积分/千 token 显示 `0.15 积分` + 人民币参考（F8-2）。
9. **用量切换维度保持筛选**（F9-1）；账单 `12345 积分` 显示 `123.45 元`（F9-2）；CSV 列与页面一致（F9-3）。
10. **充值**：支付前不得显示"积分已到账"（F10-2）；订单三种状态 + 订单号搜索取交集（F10-4）；兑换码重复使用给出明确原因（F10-3）。
11. **日志详情必须有重试时间线**：2 次尝试各自耗时与结果（F11-2）；正文超过 180 天显示"已过保留期"而非空白（F11-3）。
12. **调试台**：快捷示例存在，**点击示例不自动发送、不计费**（F12-2）；余额不足点发送 → 拦截并提示充值，且不产生上游请求（F12-3）；流式输出实时渲染，标注"按真实用量扣费"。
13. **工单**：关联请求选择器只列 90 天内本人请求（F19-1）；内容申诉自动带出规则 ID；存在未结工单时注销入口给出工单号（F19-4）。
14. **不得显示他人数据**：所有页面数据只来自本人接口；403 时显示无权限态。
15. **埋点不得包含 Key 与请求正文**。
16. **不得在前端计算账单金额**（用后端返回的元与积分两值）。

### 共用基建

### CSRF（本段最容易漏的一环）

`src/api/client.ts` **原本没有任何 CSRF 处理**，而后端 T11 第二段已给所有会话鉴权的写接口加了双提交校验。新增 `src/api/csrf.ts`：优先读非 HttpOnly 的 `csrf` cookie，其次记忆登录/`me` 响应体里的 `csrf_token`；`request()` 对非 GET 且 `/api/` 开头的请求统一注入 `X-CSRF-Token`，**调用点不手写**。漏了这一步会让所有写操作 403。

### Key 明文生命周期

创建/轮换响应 → 只写入页面级 React state → 交给 `KeySecretOnce` 展示 → 关闭即 `setRevealed(null)`，明文随组件卸载消失。不进 URL、不进 localStorage/sessionStorage、不进日志。`grep "localStorage.*key"` 为空。
