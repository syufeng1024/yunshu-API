## 1. 事实（T36 演练实测，勿重复调查）

- `docs/settlement.md` §2 明确写「以下 8 条为任务卡原文，由 `internal/recon/daily.go` 执行」——**§2 是权威规格**，`R01–R08` 是它的实现。
- 实测映射**并不成立**：

| §2 | 现状 |
| :--- | :--- |
| 1 金额守恒（日窗口 `期初+SUM=期末`） | R03 只做**逐笔余额连续性**，无日窗口 |
| 2 流水和 == 余额 | R01 ✅ |
| 3 批次余额和 == 账户余额 | **无对应检查** |
| 4 无孤儿流水 | **无对应检查**（R01 只是账户侧 LEFT JOIN） |
| 5 无未结算成功请求 | **无对应检查**（R06 查的是过期预扣） |
| 6 上游账单差 | `runExternal`（不在 R01–R08） |
| 7 日额度快照一致 | R05 ✅（本次空跑） |
| 8 配置版本可回溯 | **无对应检查** |

- R02 / R04 / R06 / R07 / R08 在 §2 里没有独立行（反向也不成立）。
- R03 实测 1 条 CRITICAL 误报：`id=33/34` 是当天实时流水，`id=35..42` 是 `created_at` 更早的种子流水，**id 顺序 ≠ `created_at` 顺序**。

## 2. 决策（D-31，需求方已确认「以 §2 为准」）

1. **§2 的 8 条为准**，`R01–R08` 是实现层编号。允许**扩展**已有检查来覆盖 §2 缺项，不得为了凑编号新增一堆空壳。
2. **R03 排序改为 `(created_at, id)`**，并在代码注释里写明「流水 id 单调性不是契约，跨天补录存在」。
3. 若某条 §2 确实需要独立检查才能表达（例如「无孤儿流水」需要 join 业务单据），**可以新增 R09+**，但必须同时更新 `Checks()`、`internal/recon/guard_test.go`（如断言条数）、`docs/settlement.md` 的映射列。
4. `runExternal`（上游账单差）算 §2-6 的实现，需在映射表里明确写「R0x / runExternal」，**不要求塞进 R01–R08**。
5. 本次不追求「跑出 0 差异」——若补检查后暴露出真实数据问题，**如实记录并判定严重级别**，不得为了让门槛好看而放宽阈值。
