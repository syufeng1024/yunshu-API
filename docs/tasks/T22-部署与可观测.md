## 4. 硬约束（违反即驳回）

1. **`/healthz` 与 `/readyz` 语义分离**：`healthz` 只反映进程、**不探测依赖**；`readyz` 探测 Redis/MySQL/config。liveness 绑 `healthz`，readiness 绑 `readyz`。**不得**让 Redis 抖动触发 K8s 重启全部网关。
2. **灰度必须按 `Authorization` 哈希粘性分流**：用 `$http_authorization`，**不得**用 `$request_id`（每请求都变，等于随机分流，会让同一 Key 在灰度期被两个版本交替处理）。
3. **内部 SLO ≠ 对外 SLA**：99.5% 是内部目标，**任何对外页面/文档不得出现**；对外只写 PRD §9.2 的承诺项。
4. **降级必须可解释**：每种降级/拒绝都要有对应错误码与 `hint`（PRD §9.8）。不得出现"静默降级"——降级即返回可读错误。
5. **资金相关 fail-close**：余额镜像缺失 → 503；限流 Redis 不可用 → 503（除并发的节点内降级）。**不得**为"提高可用性"放行资金判定。
6. **优雅停机**：`drain_deadline` 120s，`preStop` + `terminationGracePeriodSeconds` 必须大于它。
7. **账本权限**：应用账号对 `t_ledger_entry` **无 `UPDATE`/`DELETE`** 权限；可用可选触发器双保险。
8. **备份含账本**，且**恢复后必须跑对账 8 断言**；未通过不得对外服务。
9. **密钥管理**：上游渠道 Key 与日志正文 AES-GCM 信封加密；KEK 在 KMS；**禁止**把密钥写进 ConfigMap/镜像层/仓库。
10. **日志不得含敏感值**（Key、密码、上行 `Authorization`、正文未脱敏）。
11. **许可合规**：`grep -rn "QuantumNous"` 仅允许出现在**不存在**的情况；本项目不复制 new-api 代码，因此**不得**在页脚添加其署名 notice（会造成"我们基于它"的错误声明）。若将来真的引入，须先取得商务授权并改本节。
12. **告警必须可执行**：每条告警规则附「看到它该做什么」的一行说明，并指向 runbook 章节。
13. **对账差异 > 0 为 P0 告警**，且必须阻断当日发布。
14. **CVE 扫描**：高危漏洞未修复不得发版（允许带例外清单 + 负责人 + 期限）。
15. **不得对外承诺延迟数字**（P99 60s 等是设计假设，不是 SLA）。

## 5. 验收标准

| # | 判定 | 方式 |
| :--- | :--- | :--- |
| A1 | 三个镜像可构建，镜像内非 root，体积合理（gateway < 60 MB） | 复跑 |
| A2 | `kubectl apply --dry-run=client` 通过；探针绑定正确（liveness=`/healthz`） | 复跑 |
| A3 | 停 Redis：Pod **不重启**（`RESTARTS` 为 0），`/readyz` 503、被摘流量 | 手工 |
| A4 | 灰度配置：`hash $http_authorization consistent` 存在；同一 Key 100 次请求落在同一后端 | 手工（日志验证） |
| A5 | 灰度脚本：10% → 50% → 100% 每步指标对比输出 | 手工 |
| A6 | 回滚脚本：从 v2 回滚到 v1，5 分钟内完成且 `schema_migrations` 一致 | 手工演练 |
| A7 | 备份/恢复演练：全量恢复后 8 条对账断言 0 差异 | 手工演练 |
| A8 | 指标齐备：TDS §5.3 清单逐项在 `/metrics` 可见（脚本断言指标名集合） | 复跑 |
| A9 | 告警：造对账差异 → P0 告警触发；造积压 → 告警触发 | 手工 |
| A10 | 日志：抽样 10 条含固定字段；无 Key/密码/Authorization | 抽样 |
| A11 | trace 贯通：一次请求在网关日志与上游 attempt 中 `trace_id` 相同 | 手工 |
| A12 | 密钥：DB 中上游 Key 为密文；解密失败时返回明确错误不泄密 | 单测 |
| A13 | `grep -rn "99.5%\|99\.5%" web/ docs/` 只命中内部文档，不含对外页面 | grep |
| A14 | 上线检查单 30 项逐项有结论 | 人工 |

## 7. 禁止事项

- 不得把 `/healthz` 接成依赖探测（会导致雪崩式重启）。
- 不得用 `$request_id` 做灰度分流键。
- 不得在对外材料写内部 SLO。
- 不得把密钥放 ConfigMap 或镜像。
- 不得为省事跳过备份演练。
