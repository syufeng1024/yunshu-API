## 5. 硬约束（违反即驳回）

1. **顺序不可颠倒**：`0010`（Expand）必须先于 `0013`（Contract）。卡内允许 `0013` 文件先写好，但**禁止**在 `0010` 尚未应用的环境上执行。
2. **`0010` 不回填 `body_hash`**：空串代表存量，读取侧降级即可（回填 1.7 亿行不划算）。`0010` 内不得出现 `UPDATE ... SET body_hash`。
3. **新键严格弱于旧键**：`(scope, api_key_id, idem_key)` 成立 ⇒ `(scope, idem_key)` 必成立。`api_key_id` 必须 `NOT NULL DEFAULT 0`，不得为 NULL（NULL 会让唯一键失效）。
4. **`0013` 的 down 必须失败**：用 `SIGNAL SQLSTATE '45000'`，不得写成空文件或 `SELECT 1`。
5. **`0012` 只存片段不存全文**：`matched_excerpt varchar(255)`，禁止 `TEXT` 存原始消息（内容安全留痕与隐私边界见 PRD §10.1）。
6. **`0011` 的 `phone_hmac`**：`char(64)`（hex sha256），建立**唯一性不在此列**——同一手机号允许多账号吗？按 PRD 账号模型：手机号唯一，故建 `uk_user_phone_hmac`；`phone` 明文列保留但改为**可空且不加唯一键**（原唯一键迁移到 hmac 列），并在回执说明。
7. **`0015` 状态机枚举必须与 PRD 一致**：工单 `OPEN` / `RESPONDED` / `CLOSED`；审核 `PENDING` / `APPROVED` / `REJECTED`。**不得**增加 `AUTO_CLOSED`（PRD F21-2 明确要求超时**不**自动关闭）。
8. **`0017` 的 `recommend_weight` 约束**：`0` 表示不进推荐位；非 0 仅对 `listing_state='LISTED'` 的模型有效（校验在业务层，DDL 只加列 + `idx_model_recommend(recommend_weight DESC, published_at DESC)`）。`t_model` 必须已有 `published_at`，无则本卡同时补列并说明。
9. **`0018` 的配置键必须与 TDS §3.7 键表逐键一致**：**45 键**（TDS 正文的「34」是过期计数，见 errata E-07）、默认值逐字对齐、命名空间按 §3.7 归属表。`quota.overdraft_warn_days` **必须写入但 `cfg_namespace` 置 `UNASSIGNED`**（不属五个命名空间），且后台写入该键须返回 `config_value_invalid`。
10. **`t_price_group` 三档 seed**：`standard/10000`、`contract/8500`、`internal/0`。`internal` 的 `0` 是「不计费」，不是「免费打折」——seed 的 `remark` 必须写明，防止运营误读。
11. **`0018` 中 `t_rate_limit_policy` 五档 seed 必须与 PRD §3.2.1 逐列一致**：TRIAL 60/126000/22/1000、STANDARD 300/630000/110/5000、PRO 1000/2100000/367/20000、ENTERPRISE 3000/6300000/1100/100000、FREE_DEFAULT 60/60000/5/**NULL**（日额度无上限）。`scope_type='KEY'` 时 `daily_quota_micro` 恒 `0`。
12. **`0019` 不进入生产的保护**：文件首行注释 + `migrate` 执行器在 `ENV != local` 时**跳过并打 WARN**（不得报错中断，避免生产升级失败）。
13. **所有 seed 幂等**：使用 `INSERT ... ON DUPLICATE KEY UPDATE` 或 `INSERT IGNORE`，`down` 用精确 `WHERE` 删除，禁止 `TRUNCATE`。
14. **不得修改已提交的迁移文件内容**（checksum）：本卡发现 `0001–0009` 有误时，**不改旧文件**，用新增迁移修正，并在回执单列「勘误表」。
15. **`daily_quota_micro` 的「无上限」编码统一为 `NULL`**：T02 建表时 `t_rate_limit_policy.daily_quota_micro` 沿用了 TDS 的 `NOT NULL DEFAULT 0`（且 TDS 注释写「0 = 继承上一档」），而 PRD §3.2.1 默认档是**无上限**、A8 要求该列为 `NULL`。本卡必须在 `0018` 之前或之内补一次 `ALTER TABLE t_rate_limit_policy MODIFY daily_quota_micro bigint unsigned DEFAULT NULL`，并把 `FREE_DEFAULT` 种子写为 `NULL`。**不得**用 `0` 表示无上限（0 在日额度语义下等于「一分钱都不能用」）。
16. **`t_plan.stackable` 不得用于拦截购买**：TDS 注释写「同档不可重复购买」，但 PRD §3.2.1（第 323 行）明确「重复购买同一档：**允许**」。本卡只按 TDS 落默认值，**业务侧（T13）不得读该列做拒绝**；此冲突已登记为勘误 E-02。
