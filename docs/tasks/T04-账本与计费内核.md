## 1. 目标

把「钱怎么算、怎么扣、怎么退、怎么欠」一次性做成**可独立测试的纯领域层**：不依赖 HTTP、不依赖 Redis、不依赖上游。本卡的所有函数必须能在单测里用内存 MySQL 事务所驱动并通过 G-01/G-02/G-04/G-05/G-06 全部断言。后续 T07（网关）只做编排，不再出现计费逻辑。

## 4. 硬约束（违反即驳回）

1. **禁止浮点与 decimal 承载金额**：`grep -rn "float32\|float64\|shopspring/decimal" internal/ledger internal/billing` 必须为空。金额一律 `int64` 微积分。
2. **唯一舍入点**：全包只允许 `cost.go` 里出现一次 `+999)/1000`。禁止 per-token 舍入。`grep -rn "999" internal/billing` 只应命中该处（含注释）。
3. **`raw_est` 与 `est` 必须来自两个独立函数**，不得写成 `est = raw_est * 1.2`。理由是 `billing.prestimate_safety_bp` 作用于**token 预估环节**、`billing.prehold_ratio` 作用于**金额**，两者不得相乘合并成单一系数。
4. **G-02 鉴别用例必须通过**：余额 6500、`raw_est` 6000、`est` 7200 ⇒ **放行**（说明准入看 `raw_est`）。
5. **预扣上限**：`hold ≤ available × 50%`（`billing.prehold_max_ratio=0.5`），向下取整。
6. **透支不参与准入**：`overdraft_limit_micro` 只用于结算截断，**不得**计入「可用余额」。
7. **截断五条全实现**：① 单请求扣减上限 = 可用余额 + 500000；② 超出写 `t_arrears`；③ 立即置 `FROZEN_OVERDRAFT`；④ 充值优先冲抵欠费再入余额；⑤ 透支上限作准入即驳回。
8. **扣减顺序**：先赠送后充值；赠送内按 `expire_at ASC, created_at ASC`；充值按 `created_at ASC`（FIFO）。策略键 `billing.deduct_policy=fifo_expiry`，实现为注册表可选实现（默认实现即可，但接口要留）。
9. **每批次一条 DEBIT 流水**：一笔扣费跨 3 个批次则产生 3 条 `t_ledger_entry`，每条带 `batch_id` 与该批次扣减额，`SUM` 必须等于总扣费。**不得**只写一条汇总流水（否则可退基数无法复算，PRD §3.1 明确要求）。
10. **失败请求不计费**：`4xx/5xx` 结算 `consumed_micro=0`，且不产生 CONSUME 流水、不计入用量排行。释放分支 `ConsumedMicro==0` 时**必须校验存在对应预扣流水**（TDS 第一篇 §1 明确：释放未发生的预扣等于凭空加钱）。
11. **一次对外请求只结算一次**：幂等键 = `request_id`；重复结算必须被唯一键拦住，返回幂等而非二次扣费。
12. **长上下文阶梯是整单跳价**，不是分段累进：`if tok_in > threshold { 全部 tok_in 用阶梯价 }`。
13. **缓存计费结构就绪、行为关闭**：`pricing.cache_billing_enabled=false` 时 `tok_in_eff = tok_in`，且**不得**读缓存倍率列。
14. **毛利地板 SQL 语义**：`标准单价 × ratio_bp/10000 ≥ 成本价 × 4/3`，实现为整数交叉相乘 `std_micro*ratio_bp*7500 >= cost_micro*10000*10000`（等价变形须在注释里给出推导），**禁止**先算比值再比较。
15. **`internal` 分组（`ratio_bp=0`）不参与地板校验**，改用 PRD §6.4 F16-5 四项约束（由 T15 实现校验）。
16. **时间**：所有 `created_at` 由 `clock.Now().UTC()` 取，禁 `time.Now()`。
17. **事务边界**：预扣单事务 ≤ `200ms`（`prehold.TxnTimeout`）；余额 CAS 与流水写入**必须同事务**。
18. **不引入批次级扣减明细表**（GR-05），依靠 `t_credit_batch.remaining_micro` + 流水 `batch_id` 还原轨迹；若实现中发现无法还原，**停止并报回**，不得自行加表。

## 5. 验收标准

| # | 判定 | 方式 |
| :--- | :--- | :--- |
| A1 | `go test ./internal/ledger/... ./internal/billing/... -race` 全绿 | 复跑 |
| A2 | G-01 用例通过：1000 输入 + 500 输出、单价已知 → `cost_micro` 与手算一致（误差 0） | 单测 |
| A3 | **G-02 用例通过**：余额 6500 / `raw_est` 6000 / `est` 7200 → 放行且 `hold==3600`（=6500×50% 向下） | 单测 |
| A4 | 截断用例：余额 100、消费 600 → 余额 `-500`（不更低）、`t_arrears` 记 0（因为 100+500=600 恰好覆盖）；余额 100、消费 700 → 余额 `-500`、`t_arrears=100`、状态 `FROZEN_OVERDRAFT` | 单测 |
| A5 | 充值 200 后：`t_arrears` 归零、余额 `+100`、状态回 `NORMAL` | 单测 |
| A6 | 批次顺序用例：赠送 A（到期早）、赠送 B（到期晚、创建早）、充值 C → 扣 3 次，顺序为 A→B→C，且产生 3 条 DEBIT 流水、`SUM == 总扣费` | 单测 |
| A7 | 重试只结算一次：同 `request_id` 结算两次，第二次返回幂等，余额只减一次 | 单测 |
| A8 | 失败请求：`consumed=0` 时全额释放预扣；**若预扣流水不存在则拒绝释放并报错** | 单测 |

## 7. 禁止事项

- 不得让 `internal/ledger` import `internal/gw`、`net/http`、`internal/redisx`（领域层不得依赖基础设施，便于单测）。
- 不得把「预扣」实现成 Redis 计数（GR-02：Redis 只做拦截判断，账本真相在 `t_ledger_entry`）。
- 不得合并「准入」与「预扣」为同一个数值字段。
- 不得在结算里做「差额纠偏」（GR-04：不做调价差额纠偏，按配置版本号事后圈定）。
- 不得自行新增 `t_ledger_batch_detail` 之类明细表（GR-05）。
