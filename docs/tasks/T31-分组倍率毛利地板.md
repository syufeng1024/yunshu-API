## 1. 目标

PRD §6.4 F16-5 要求「保存或修改**分组倍率**、**模型单价**时」都校验毛利地板。当前只做了模型单价一侧，分组倍率可以随便改。本卡把分组这一半补齐，并落实 `internal` 分组的四项例外约束。

## 2. 现状（已核实，直接引用）

| 事实 | 位置 |
| :--- | :--- |
| 价格侧地板已实现：`3 × price × ratioBP ≥ 40000 × cost` 整数交叉相乘，失败返回 `invalid_request_body` + 差额文案；`internal`（`ratioBP <= 0`）跳过 | `internal/control/ops/pricing.go:875-910`（常量 `floorCrossFactor=40000`、`floorScale=30000` 在 `:21-30`） |
| **分组侧完全没有校验**：`UpdateGroup` 直接写 `ratio_bp`，无成本价读取、无地板比较、无 `internal` 例外处理 | `internal/control/ops/group.go:119`（`UpdateGroup`） |
| `internal` 分组目前只做了「remark 必填 + 审计」，没有四项约束中的 ②二次确认 与 ④渠道限定 | `internal/control/ops/group.go`（`groupCodeInternal` 常量已在 `:19`） |
| 配置键已定义但未被分组侧使用 | `internal/config/key.go:34-37`（`pricing.min_margin_bp` / `plan_min_margin_bp` / `max_bonus_ratio_bp`） |

## 3. 决策（D-28，本卡内不再重议）

1. **口径唯一**：复用 `pricing.go` 的整数交叉相乘（`成本 × 10000 ÷ 7500` 向上取整），**不新造公式**；把该比较抽成共享函数供两处调用，禁止在 `group.go` 里复制一份常量。
2. **校验对象**：改 `ratio_bp` 时，对被该分组范围内的**全部启用模型**（`model_scope_mode` 决定范围：ALL 取全部已上架且有成本价的模型；SELECTED 取其 `model_ids`）逐条校验。
3. **`internal`（`ratio_bp == 0`）不参与地板**，改为四项约束：
   - ① 仅运营可设（现有 `PermPricingWrite` 已满足，**加一条测试锁住**）；
   - ② 保存须二次确认并留痕：请求必须带 `confirm: true` **且** `reason` 非空，审计行写操作人 / 理由 / 时间；缺任一项 → `invalid_request_body`；
   - ③ 毛利视图单独列示、不计入收入与毛利：检查 `overview.go` 的毛利聚合是否已排除 `internal`，**未排除就修**；
   - ④ 可用渠道必须限定为非主力渠道（PRD §3.5）：落地为「`internal` 分组保存时，`channel_scope` 不得包含当前权重最高的渠道」，违反 → `invalid_request_body` 并说明命中渠道。
4. **缺成本价降级为「警告 + 二次确认」**，不得静默上架：非 `internal` 分组改倍率时，若范围内存在无成本价的模型，**不拒绝**，但响应必须带 `warnings[]`（列出模型名），且要求 `confirm: true` 才落库；未确认 → `invalid_request_body`。
5. **不动表结构**；`t_price_group.min_margin_bp` 已存在，本次只读取不新增列。
6. **错误码复用** `apierr.CodeInvalidRequestBody`（与价格侧一致），文案必须含「差额 + 涉及模型/渠道」，**不新造码**。
