## 1. 目标

把「65 个错误码 + 统一错误体 + 响应头 + SSE 错误帧 + `request_id` 兜底」做成**唯一写出口**。任何业务代码不得自己拼错误 JSON。本卡是 G-10 / G-11 与附录 E 的代码化载体，也是客户端 SDK 兼容性的基础。

## 4. 硬约束（违反即驳回）

1. **唯一写出口**：`grep -rn "http.Error\|w.WriteHeader\|json.NewEncoder(w)" internal/ --include=*.go | grep -v internal/apierr` 必须为空（允许的健康检查除外）。
2. **错误体结构不因协议而异**：OpenAI / Anthropic / 百炼三种入站协议**共用同一个错误体结构**；差异只体现在 HTTP 状态码与响应头。
3. **`request_id` 恒存在且同值**：写出路径在标识为空时自动生成 UUIDv7 形态并**写回结构体**，保证 `X-Request-Id` 头与体内 `request_id` 永远相等。不得依赖调用方逐处 `WithRequestID`。
4. **非限流类三字段缺省**：`reset_at` / `limit` / `remaining` **不出现**（不是 `null`）。402 例外：带 `limit` / `remaining`，**不带** `reset_at`。
5. **402 字段语义**：`remaining` 为积分且**可为负**（负值表达欠费）；`limit` 为透支上限；头 `X-Credits-Remaining` 与体 `remaining` **必须取自同一变量**。
6. **429 的 `code` 取恢复最晚者**：`daily_quota_exceeded` > `rpm/tpm` > `concurrency`。同时触顶的 RPM 与 TPM 取 RPM（按维度声明顺序）。
7. **`limit` / `remaining` / `reset_at` 只描述主维度**；其余维度只进 `message`。理由：客户端会用 `limit − remaining` 反推剩余量。
8. **流式永久不返回 `X-Credits-Consumed`**，且正常结束的流**不追加结算帧**。实际扣费唯一透出通道是错误帧的 `credits_consumed`。
9. **码与文案分离**：`hint` 与 `message` 由元数据表 + 参数插值生成，业务代码只传参数。
10. **`upstream_error` 类不得 500**：`model_not_available` 用 **503**（不是 404/500）；`upstream_capacity_exceeded` 用 **503**（不是 429）。
11. **码总数 = 65**：任何新增/删除必须同步 `codes.go`、`codes_test.go`、`docs/error-codes.md`，且 PR 说明里给出增删理由。**禁止**为了"对齐文档头部数字"而删码或改断言（TDS 明确记录过这类偏差，抹平会让下次偏差不可发现）。
12. **必含的 4 个 TA-1.2 新码**：`idempotency_key_reused`、`content_policy_violation`、`account_frozen_due_to_overdraft`（由「V1 未开发」改为**必须实现**）、`rate_limiter_unavailable`。
13. **`error` 顶层对象**：体形如 `{"error":{...}}`，不得平铺到顶层。
14. **不得在错误体里泄露**：上游渠道名/地址、白名单内容、他人 Key 是否存在、堆栈、SQL。

## 7. 禁止事项

- 不得让各业务包自建错误结构。
- 不得把 `retry_after_seconds` 写成字符串或省略。
- 不得为 402 加 `reset_at`（会让客户端做白等的自动重试）。
- 不得把上游 429 映射成客户端 429（见 T08）。
- 不得为了"减少码数"合并语义不同的码（如 `model_not_authorized` vs `model_not_in_group`）。
