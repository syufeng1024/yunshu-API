## 5. 硬约束（违反即打回）

1. **`Auth.KeyID` 必须是真实存在的 Key ID**。禁止用 `0`、`-1` 或任何哨兵值代替——`§2` 列的 8 处依赖会全部失效（模型授权查不到、限流计数串号、日志归属错误）。

2. **签名协议（本卡唯一定义，实现方不得自创）**：

```
canonical = "v1\n" + ts_sec + "\n" + body_sha256_hex + "\n" +
            user_id + "\n" + key_id + "\n" + key_name + "\n" +
            group_code + "\n" + group_ratio_bp + "\n" +
            ip_rule_ver + "\n" + key_expiry_ms
sig = base64(HMAC-SHA256(INTERNAL_CALL_SECRET, canonical))

请求头：X-Yunshu-Internal-Sig: v1:<ts_sec>:<sig>
```

   - `body_sha256_hex` 是**请求体的 SHA-256 十六进制**，绑定后篡改 body 即验签失败；
   - 时间窗 **±60 秒**，超出即 401；
   - 比较必须用 `hmac.Equal`（常量时间），禁止 `==` 比较字符串；
   - 验签失败一律 `401` + `invalid_api_key` 同款**无语义**文案，不得暴露"签名不对/过期"的区分（避免成为探测面）。

3. **内部端点只在内网存在**，三重保证缺一不可：
   - compose 中 gatewayd **不新增任何 ports 映射**（现有 `18080:8080` 保持不变，`/internal/` 靠签名兜底）；
   - `deploy/nginx/gateway.conf` 增加 `location /internal/ { return 404; }`；
   - `INTERNAL_CALL_SECRET` 为空时**不注册该路由**，并在启动日志 warn。

4. **`INTERNAL_CALL_SECRET` 不得与 `SESSION_SECRET` / `CHANNEL_KEY_KEK` / `LOG_BODY_KEK` 复用**，长度 ≥ 32 字节随机。缺失时：gatewayd 不注册路由（见约束 3），controld 调用该端点返回 `503 config_unavailable`。

5. **P05 之外的阶段一个都不能跳过**。IP 白名单（P06）、模型授权（P07）、幂等（P08）、预扣（P10）、限流（P11）、上游分发（P12）、结算与日志必须全部照跑。`grep` 审计：`internal.go` 里装配的阶段名必须覆盖 `P06 P07 P08 P09 P10 P11 P12 P13 P14`。

6. **SSE 必须逐帧透传，不得缓冲**。controld 侧禁止 `io.ReadAll` 后再写；必须 `http.Flusher` 逐块刷出，且**禁用响应压缩**。响应头需带 `Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。

7. **不得改动 `/v1/*` 的既有行为与契约**。本卡对公网 API 零影响；`git diff` 中 `p01`–`p04`、`p12`–`p14` 的业务逻辑不得出现语义变化（P05 只允许加 §4 第 2 项那一处短路）。

8. **不得新增计费旁路**。调试台与真实调用走同一条预扣/结算代码；禁止在 controld 里自行扣余额或写 `t_usage_record`。`grep -rn "t_usage_record" internal/control/` 应零命中（写侧）。

9. **文件域边界**：只碰 §4 列出的路径。禁止碰 `web/**`（段 2）、`internal/settle/**`、`internal/ledger/**`、`internal/platform/migrate/**`、`docs/tasks/README.md`。

### 11.5 验收实测发现的缺陷（已修，提交 `851c6da`）

静态审计（`grep -n "location /internal/" deploy/nginx/gateway.conf` 有命中）会误判为通过，但**跑真实栈测出来的结果相反**：

| 实测 | 结果 | 含义 |
| :--- | :--- | :--- |
| `POST http://127.0.0.1:8088/internal/v1/chat/completions`（nginx） | **405** | 拦截没生效，请求被 SPA 兜底 location 接走 |
| `POST http://127.0.0.1:18080/internal/v1/chat/completions`（gatewayd 直连） | **401** | 端点确实从宿主机可达，只剩 HMAC 一道门 |
| `docker exec yunshu-stack-web grep -rn internal /etc/nginx/` | 零命中 | 容器里根本没有这条规则 |

**根因**：`deploy/Dockerfile.web:36` COPY 的是 **`nginx/default.conf`**；而卡面 §4 第 13 项指的 `nginx/gateway.conf` 是**灰度入口**的另一份配置（`split_clients` 分 stable/canary 池），web 容器不加载它。规则写对了内容、写错了文件。

**修正**：在 `default.conf` 的 server 块加 `location ^~ /internal/ { return 404; }`（用 `^~` 前缀匹配，防止被其后的正则 location 抢走），并注释写明两份 conf 的分工。`gateway.conf` 那份保留——灰度场景下仍有意义。

**复测**：8088 `/internal/` → **404**；首页 200；`/api/public/plans` 200；三进程 healthy。三重门（不额外发布端口 / nginx 404 / 无密钥不注册）至此才真正齐全。
