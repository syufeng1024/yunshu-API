## 4. 判定口径（统一，不得自创）

| 结论 | 含义 |
| :--- | :--- |
| ✅ 通过 | 有自动化用例且通过，**或**有可复核的手工证据（截图 + 步骤 + 数据） |
| ⚠️ 有条件通过 | 功能可用但存在已登记的偏差/未覆盖分支，且偏差有理由、影响可接受 |
| ❌ 不通过 | 无证据、断言不成立、或用例被 skip |

**证据三要素**：可重复的命令或步骤、可核对的输出/截图、可定位的代码位置（文件:行）。缺任一项即 ❌。

## 5. 硬约束（违反即驳回）

1. **82 条一条不少**：编号必须与 PRD 附录 D.3 完全一致（含 F1-7/F1-6 这种表内乱序也要原样保留，**不得**自行重排编号）。
2. **`⚠️` 不得超过总条数的 10%**（即 ≤ 8 条），且每条必须指向 `deviations.md` 的登记项。
3. **标「测试」的条目必须给自动化用例名**，不接受手工截图。
4. **不得把"原型待改造"当作偏差**：原型与文档不一致一律以实现文档为准（PRD 头部已明确）。
5. **偏差登记必须双向**：既要记"实现偏离文档"，也要记"文档本身有误"（后者进 `errata.md`，**不得**悄悄按实现改文档）。
6. **Go/No-Go 门槛**（全部满足才可 Go）：
   - 82 项中 ❌ == 0，⚠️ ≤ 8 且均已登记；
   - G-01–G-12 全 ✅；
   - 65 码断言通过且枚举行数一致；
   - 8 条对账断言在演练中 0 差异；
   - 14 条 CI 门禁全绿；
   - 无 P0 级开放问题；
   - 备份恢复演练通过；
   - 内部 SLO 未出现在任何对外页面。
7. **不得为了让结论好看而改判定口径**；口径变更须先在本卡修订并说明理由。
8. **文档回写只做两件事**：补迁移编号、按 `errata.md` 修事实错误。**不得**借机改设计或"顺手优化"措辞。
9. **`file-index.md` 必须能覆盖全部交付物**，且每条有职责描述（供后续接手人定位）。
