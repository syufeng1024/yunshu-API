## 2. 必须先回答的问题（决定这张卡的形状）

**V1.0 接哪一家上游的账单？**

| 方案 | 代价 | 适用 |
| :--- | :--- | :--- |
| A. 管理端**手工导入**（CSV/JSON，`MANUAL_UPLOAD`） | 小：一个端点 + 校验 + 审计 | 上游无 API 账单，或只对接 1–2 家 |
| B. 适配器定时拉取（百炼 / DeepSeek） | 大：每家一个 client、鉴权、分页、重试、幂等 | 上游有开放账单 API |
| C. 两者都要 | 最大 | 长期 |

**建议 V1.0 走 A**，理由：账单表已给 `MANUAL_UPLOAD` 留了枚举；`runExternal` 的近似匹配就是为「导入行没有 request_id」设计的；B 家 API 形态未定，做了也是猜。

> 若需求方选 B，本卡拆成 B1（适配器接口 + 一家实现）与 B2（其余家），不要一张卡塞两家。

## 3. 范围（按方案 A）

| # | 内容 |
| :--- | :--- |
| 1 | `POST /api/admin/upstream-bills/import`：接收 `channel_id` + `bill_period` + 行数组（或 CSV 上传），逐行校验后写 `t_upstream_bill`（`bill_adapter='MANUAL_UPLOAD'`） |
| 2 | 幂等：同一 `(channel_id, bill_period, bill_no)` 重复导入不得报错、不得重复计账——`ON DUPLICATE KEY UPDATE` 覆盖同一行，或跳过并计入 `skipped` |
| 3 | 校验：`bill_period` 格式、`amount_micro ≥ 0`、`tokens_*` 非负、`channel_id` 存在、`raw_row` 原样保留（不丢列） |
| 4 | 审计：沿用 `t_admin_audit_log`（与 config/channel 写操作同一套），记录导入行数与操作人 |
| 5 | RBAC：需要 `PermChannelWrite` 或新增一个更窄的权限；**不得**使用只读权限 |
| 6 | 单测：① 导入 2 行 → 2 行落库；② 重复导入同一批 → 行数不变；③ 缺 `bill_no` → 400 `invalid_request_body`；④ 越权 → 403 `permission_denied` |

## 4. 硬约束

1. **不加新表**；确需加列（如导入批次 id）才加迁移，且必须重生成 `checksums.golden` 并同步 `guard_test.go` / `migrate_test.go` 的表数与版本数（见交接单环境事实）。
2. `amount_micro` 只接受 int64 微积分；拒绝浮点输入（D-07）。
3. **不得**在导入时改 `t_usage_record` 任何行——对账是读侧比对，不是写侧修正。
4. **不得**为了让 R05/R09 好看而伪造账单行。
5. 不 commit / 不 push。

## 5. 验收口径

| # | 查什么 | 通过标准 |
| :--- | :--- | :--- |
| 1 | 真能导入 | 在演练库导一份手工账单（≥2 行）→ `SELECT COUNT(*)` 与导入行数一致 |
| 2 | 幂等 | 同一批导两次 → 行数不变 |
| 3 | `runExternal` 不再空跑 | `recondrill --db yunshu_drill` 的 `external` 计数 > 0，且账单行与 `t_usage_record` 能匹配上（至少 1 条 `MatchMode=DAILY`） |
| 4 | 反证 | 故意把某行 `amount_micro` 加大 → `runExternal` 必须报 MONEY 类 diff 且 `result=FAIL` |
| 5 | 越权 | 无写权限的账号导入 → 403 `permission_denied` |

## 6. 一个必须先讲清的口径问题

`runExternal` 当日**没有账单就静默通过**（`daily.go:903`）。这意味着：即使本卡做完，只要运营没导入账单，门槛 4 的「0 差异」仍然是**空跑**。

本卡**不要求**改 `runExternal`（那会引入「每天都必须有账单」的告警噪音），但必须做到：

- 演练/举证时装**显式导入**一份账单，并在报告里写清「本次有 N 行账单参与比对」；
- 在 `docs/ops-runbook.md` 的日对账步骤里补一句「先确认当日账单已导入，否则 external 段无意义」。

是否把「连续 N 天无账单」升级成运维告警，属 OI 级决策，留待需求方。
